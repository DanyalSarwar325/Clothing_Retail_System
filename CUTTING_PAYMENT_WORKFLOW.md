# Cutting Department Payment Workflow

## Overview
The Cutting department now follows a special workflow where payment is calculated based on **items actually scanned by the Sewing department**, not just items generated by Cutting. This prevents payment for barcodes that are generated but never used (not pasted on products).

## Workflow Process

### 1. **Barcode Generation (Cutting Department)**
```
┌─────────────────────────────────┐
│ Cutting generates 10 barcodes   │
│ Example: Design "Wedding Suit"  │
└────────────────┬────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐
│ Barcodes saved to DB with:      │
│ - status: "generated"           │
│ - currentDepartment: "Cutting"  │
│ - NOT visible in cutting count  │
└────────────────┬────────────────┘
                 │
        Products are printed
        and sent to sewing
                 │
                 ▼
┌─────────────────────────────────┐
│ Cutting Dashboard Shows:         │
│ ✓ Payment: ₨0 (nothing scanned)  │
│ ✓ Total Scans: 0                │
│ Generated barcodes are hidden    │
└─────────────────────────────────┘
```

### 2. **Sewing Department Scans (Confirmation)**
```
┌─────────────────────────────────┐
│ Sewing receives products        │
│ Scans barcodes during sewing    │
│ Example: Scans 8 out of 10      │
└────────────────┬────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐
│ For each scanned barcode:       │
│ - status changes: "scanned"     │
│ - Added to departmentHistory    │
│ - Now counted in payment        │
└────────────────┬────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐
│ Cutting Dashboard NOW Shows:     │
│ ✓ Payment: ₨[8 × rate] per unit │
│ ✓ Total Scans: 8                │
│ ✓ Only scanned items counted    │
└─────────────────────────────────┘
```

### 3. **Unused Barcodes (Not Scanned)**
```
2 barcodes were never scanned by Sewing:
├─ status: "generated"
├─ NOT in cutting payment
├─ Can be reused or disposed
└─ Reason: Not pasted on products

Result: Cutting only paid for 8 items, not 10!
```

## Database Schema Changes

### Barcode Status Enum
```typescript
status: "generated" | "scanned" | "available" | "sold" | "returned"
```

**Status Meaning:**
- `generated`: Barcode created by Cutting but not yet scanned by Sewing (NOT PAID)
- `scanned`: Barcode scanned by Sewing (PAID - for Cutting only)
- `available`: General status for other departments
- `sold`: Item has been sold
- `returned`: Item has been returned

## API Changes

### 1. Payment Calculation `/api/payment/pending`
**For Cutting Department Only:**
```javascript
// Old: Count all cutting department scans
const scanCount = countDocuments({
  "departmentHistory.department": "Cutting"
})

// New: Count only SCANNED barcodes
const scanCount = countDocuments({
  status: "scanned",  // ← NEW FILTER
  "departmentHistory.department": "Cutting"
})
```

### 2. Payment by Design `/api/payment/pending/by-design`
**For Cutting Department Only:**
- Same filter applied: only count barcodes with `status: "scanned"`
- Other departments work as before

### 3. Department Summary `/api/payment/department`
**For Cutting Department Only:**
- Only count barcodes with `status: "scanned"` in totalScans calculation
- Other departments count all scans normally

## Example Scenario

### Cutting Department Workflow
```
Day 1 - Cutting Person (User: John)
├─ Creates 10 barcodes for "Bridal Suit" design
├─ Barcodes stored with status: "generated"
├─ Dashboard shows: Payment = ₨0, Total Scans = 0
└─ Products are printed and sent to sewing

Day 2 - Sewing Person (User: Fatima)
├─ Receives products
├─ Scans 8 out of 10 barcodes
├─ Each scan:
│  ├─ Barcode status changes: generated → scanned
│  ├─ Added to departmentHistory with "Sewing"
│  └─ Counted in cutting payment calculation
└─ 2 barcodes never scanned (not pasted on products)

Day 3 - Cutting Dashboard (John's View)
├─ Payment: ₨800 (if rate is ₨100/unit)
│  └─ Calculation: 8 scanned items × ₨100/unit
├─ Total Scans: 8
├─ By Design:
│  └─ "Bridal Suit": 8 scans = ₨800
└─ Note: 2 generated but unused barcodes are ignored
```

## Other Departments - NO CHANGE

All other departments continue working as before:
- Quality, Handmade, Adda Work, Patching, Press, Packing, Store
- Payment is calculated based on all scans (no "scanned" status filter)
- Their workflow and payment logic remains unchanged

## Benefits

✅ **Accurate Payment**: Cutting only paid for items actually used
✅ **Waste Prevention**: Unused barcodes don't count toward payment
✅ **Quality Control**: Ensures accountability between departments
✅ **Reusability**: Generated but unused barcodes can be reprinted if needed
✅ **Clear Workflow**: Visual feedback when items are confirmed by next department

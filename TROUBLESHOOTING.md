# Troubleshooting Guide

## Common Issues & Solutions

### Issue 1: Cutting Dashboard Shows ₨0 After Generating Barcodes

**Problem:** Generated barcodes but payment still shows ₨0

**Expected Behavior:** This is CORRECT! ✓
- Barcodes are saved as `status: "generated"`
- Payment only shows after Sewing scans them
- This is the intended behavior to prevent payment for unused items

**What to Do:**
1. Go to Sewing Department
2. Scan the barcodes
3. Return to Cutting Dashboard
4. Payment should now update

**How to Verify:**
```javascript
// Check database
db.barcodes.find({ design: "Your Design" }).pretty()

// You should see:
{ status: "generated", ... }  // Not counted
```

---

### Issue 2: Sewing Scans Barcode But Cutting Payment Doesn't Update

**Problem:** Sewing department scanned barcode, but payment remains ₨0

**Possible Causes:**

#### Cause A: Barcode not actually scanned by Sewing
**Solution:**
1. Verify scan was successful in Sewing interface
2. Check for error messages in scan response
3. Try scanning again

#### Cause B: Dashboard not refreshed
**Solution:**
1. Press Ctrl+F5 (hard refresh)
2. Close and reopen browser
3. Check in incognito/private mode

#### Cause C: Scan was by wrong person
**Problem:** Scan must include `scannedBy` field with correct user
**Solution:**
1. Verify user is logged into Sewing account
2. Check that `scannedBy` matches user name
3. Re-scan if needed

**Debug Check:**
```javascript
// Check what was actually saved
db.barcodes.find({ 
  design: "Your Design" 
}).pretty()

// Look for:
{
  status: "scanned",     // Should be "scanned" not "generated"
  departmentHistory: [{
    department: "Sewing",
    scannedBy: "Fatima"   // Should match logged-in user
  }]
}
```

#### Cause D: Wrong filter in code
**Solution:** Check that payment API has the new filter
```typescript
// Should look like:
if (department === "Cutting") {
  scanCount = countDocuments({
    status: "scanned",  // ← This filter MUST be here
    "departmentHistory.department": "Cutting"
  })
}
```

### Issue 3: Payment Count is Too High

**Problem:** Payment shows payment for more items than scanned

**Likely Cause:** Multiple status values in database
- Some barcodes might be `"available"` (old system)
- Some might be `"scanned"`
- Code might not be filtering correctly

**Solution:**
```javascript
// Check database for all statuses
db.barcodes.aggregate([
  { $group: { _id: "$status", count: { $sum: 1 } } }
])

// You should see:
{ _id: "generated", count: 50 }
{ _id: "scanned", count: 35 }
{ _id: "available", count: 15 }

// If you see "available" for recent items:
// Update them: db.barcodes.updateMany(
//   { status: "available", createdAt: { $gt: new Date("2024-01-01") } },
//   { $set: { status: "generated" } }
// )
```

### Issue 4: Sewing Cannot Scan Barcode

**Problem:** Scan fails with error message

**Common Errors:**

#### Error: "Barcode not found in database"
**Solution:**
1. Verify barcode was printed correctly
2. Check barcode data matches what's in database
3. Ensure barcode was generated by Cutting first

#### Error: "Already scanned by Sewing department"
**Expected:** This prevents duplicate scans
**Solution:** 
1. Check if barcode was already scanned
2. If legitimate, it's preventing double-counting (correct!)
3. To re-scan same barcode, contact administrator

#### Error: "Barcode data is required"
**Solution:**
1. Ensure scanner is working
2. Check barcode is properly printed
3. Try scanning a known good barcode

---

### Issue 5: Other Department Payment Affected

**Problem:** Quality/Handmade/etc. payment changed unexpectedly

**Expected Behavior:** Should NOT be affected ✓

**If It Is:**
1. Check that filter is only for Cutting
2. Verify code:
```typescript
if (department === "Cutting") {
  // ← Should filter ONLY for Cutting
  scanCount = countDocuments({ status: "scanned", ... })
} else {
  // ← Other departments unchanged
  scanCount = countDocuments({ ... })
}
```

### Issue 6: Database Migration Issues

**Problem:** Old data is showing wrong values

**Solution - Check Old Barcodes:**
```javascript
// Find barcodes with "available" status
db.barcodes.find({ status: "available" }).count()

// These won't be counted for Cutting payment
// They can be manually updated if needed:
db.barcodes.updateMany(
  { 
    status: "available",
    currentDepartment: "Cutting",
    createdAt: { $lt: new Date("2024-01-01") }
  },
  { $set: { status: "generated" } }
)
```

### Issue 8: Real-Time Updates Not Working

**Problem:** Dashboard doesn't update when Sewing scans

**Causes & Solutions:**

#### Cause 1: No automatic refresh
**Solution:** Add manual refresh button or set up polling
```typescript
// Add in component:
const [refreshKey, setRefreshKey] = useState(0);

const handleRefresh = () => {
  setRefreshKey(prev => prev + 1);
};

// Use key to force re-render
<PaymentDisplay key={refreshKey} ... />
```

#### Cause 2: Fetch caching
**Solution:** Ensure no caching in fetch
```typescript
const response = await fetch(`/api/payment/pending...`, {
  cache: "no-store",  // ← Important!
  headers: { 
    "Cache-Control": "no-cache" 
  }
});
```

## Verification Checklist

When troubleshooting, verify these items:

### Database Level
- [ ] Barcodes have correct `status` field
- [ ] Barcodes have correct `departmentHistory`
- [ ] `scannedBy` field is populated
- [ ] Dates are correct

### API Level
- [ ] Endpoints return correct counts
- [ ] Filters are applied for Cutting only
- [ ] Other departments unaffected
- [ ] Error responses are clear

### UI Level
- [ ] Components display correct values
- [ ] Payment updates after scan
- [ ] By-design breakdown is accurate
- [ ] Department summary matches individual

### Workflow Level
- [ ] Generated → not counted
- [ ] Scanned → counted
- [ ] Unused → remain generated
- [ ] Other departments → unchanged

## Quick Fix Commands

```javascript
// Show all barcode statuses
db.barcodes.aggregate([
  { $group: { _id: "$status", count: { $sum: 1 } } },
  { $sort: { count: -1 } }
])

// Count cutting payment
db.barcodes.countDocuments({
  status: "scanned",
  "departmentHistory": {
    $elemMatch: { department: "Cutting" }
  }
})

// Find unused barcodes
db.barcodes.find({ status: "generated" }).count()

// Find all scanned by cutting
db.barcodes.find({ 
  status: "scanned",
  currentDepartment: "Cutting"
}).count()

// Find by design
db.barcodes.find({ design: "Wedding Suit" }).count()
```
